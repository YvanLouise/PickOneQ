# 拾一问 PickOneQ

面向大学生的跨学科知识探索本地 Web App。通过问题、主动回忆、针对性反馈、来源解释与关联问题，帮助用户发现并修正自己的理解缺口。

## 运行

需要 Node.js 22 或更高版本。

Windows 用户可以直接双击 `启动拾一问.cmd`。脚本会检查运行环境、在首次启动时安装依赖、构建应用并打开浏览器；关闭脚本窗口会停止本地服务。

```powershell
npm install
npm run dev
```

打开 `http://127.0.0.1:4311`。生产模式：

```powershell
npm run build
npm start
```

默认端口是 `4311`，可通过 `PORT` 环境变量修改。服务仅监听本机回环地址。

## 模型与本地数据

- 没有 API Key 时进入明确标注的“精选示例”模式，回答会保存，但不会生成 AI 评价。
- 模型优先适配 DeepSeek，支持 `deepseek-flash` 和 `deepseek-v4-pro`。保存 Key 前会先验证连接。
- 选择“记住 Key”时使用 Windows 系统凭据存储；否则仅保存在当前服务进程内。Key 不进入浏览器、本地学习记录或导出备份。
- 学习记录和生成题目写入 `.local/`，该目录已被 Git 忽略。可在“我的”中导出、恢复或清空；备份恢复会先校验状态、题目、引用和资料版本。
- 启动时如果发现损坏的数据文件，应用会保留带有 `.corrupt-时间戳.json` 后缀的原文件，再以安全的空白状态启动。

## 内容质量流程

资料池位于 `server/data/sources.json`，覆盖六个领域，每个领域五份可追溯资料。重新抓取资料：

```powershell
node scripts/prepare-sources.mjs --refresh
```

AI 候选题先校验结构、原文引用、时效性和重复度，再由第二次独立模型调用核验前提、答案、推理、例子、引用与新颖性；全部通过才会进入问题流。个人反馈中的正确判断、事实错误、推理跳跃和关键补充也必须逐条对应用户原话与资料证据。用户举报后，该题会立即暂停推荐并保留原记录。

## 验证

### 情境提问与连续探索（内容版本 2）

- 14 道新版精选示例使用具体情境，保留原版供历史、草稿、收藏和复习访问。新题流只推荐新版；首页不提前显示概念名。
- 选择和理由分别保存，可只选择或自由回答。仅选对不视作掌握，不触发复习通过。
- 供题增加必要条件、不剧透、选项公平与明确任务核验。内部四项编辑评分（易懂、参与、张力、收益）各至少 3 分、合计至少 15 分才入流；分数不是用户成绩，也不是学习效果指标。
- “继续聊这一问”支持多轮、来源展示、停止、失败重试和刷新恢复。每轮通常调用模型两次，核验前不展示正文。上下文采用最近六轮及更早最多十二轮的原文摘录，不让模型编写历史摘要；记录本身仍完整保留。
- 对话绑定题目版本，不增加新题计数，不自动安排复习。未发送的文字存浏览器，已发送轮次随本地备份导出；清空或恢复会同步清理浏览器草稿。
- 首次加载旧状态时保存 `.before-scenes-时间戳.json` 备份再迁移；进行中的旧请求恢复为可重试状态。代码更新后需重启本地服务，临时会话 Key 需要重新输入。
- 自动测试使用合成模型回复验证流程，不代表真实模型内容已获人工验收。发布试用前仍需每领域抽查十道动态题，并安排真实用户访谈；不能把自动评分当成实际回答意愿。

### 自动备题队列

- 配置 Key 并完成首次设置后，后台默认维持 6 道未读、已独立核验的 AI 新题。启动服务、打开应用、取用题目或暂停问题时都会检查库存；无需手动点击。
- 每道候选题由一次模型调用同时生成问题、一句话答案、2—4 步推理、例子、误区、提示、概念揭示和迁移问题，再由第二次独立调用核验。未通过结构、来源、去重或情境质量检查的内容不会进入题流。
- 后台始终串行准备，作答评价或连续对话进行时暂停补题，避免并发消耗。失败后从 30 秒开始指数退避，最长 30 分钟；不再限制服务进程内的总尝试次数。
- “我的 → 模型与资料”显示已核验库存、目标数量、生成／核验阶段、失败原因和预计重试时间，也可手动立即补充一道。

```powershell
npm run check
npm test
npm run build
```

测试覆盖本地 API、草稿恢复、复习间隔、内容隔离、异常降级、凭据不落盘、动态题双重核验和引用完整性。设计与浏览器验收截图位于 `design/`。

## Android 打包与线上发布

双击 `打开安卓打包发布工具.cmd`，或运行 `npm run android:release`。独立管理页可生成 Debug/Release APK、配置长期签名、创建 GitHub Release、上传 APK、写入升级清单，并在上传失败后复用已生成的 APK 重试发布。

Android 包连接已经部署的拾一问 HTTPS 服务；GitHub Release 只负责 APK 与升级清单的分发。完整步骤见 `docs/android-release.md`。
